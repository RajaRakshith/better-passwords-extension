Pair once

Apple's extension drops its connection whenever the browser idles, and every reconnect asks for a new code. This one keeps the connection open until you quit the browser.

Or use Touch ID

With the optional Mac companion app, you confirm with your fingerprint and the code is entered for you. Your browser never gets Accessibility access.

Suggestions in the page

Click a login field and pick an account, like in Safari. Use the arrow keys if you prefer the keyboard.

Apple keeps your passwords

Every request goes to the password helper built into macOS, over Apple's own encrypted pairing. Nothing is stored or sent anywhere else.

How it works

  1. ExtensionAsks for logins for the site you're on
  2. Apple's helperShips with macOS 14 and later. Checks the pairing, talks to iCloud Keychain
  3. Apple PasswordsYour passwords, where they already are

The extension speaks the same protocol as Apple's iCloud Passwords extension: SRP pairing with the code your Mac shows, then AES-GCM encryption. The difference is that it keeps the session. Read the architecture and the threat model.

Install

You need a Mac with macOS 14 (Sonoma) or later, signed in to iCloud with Passwords turned on.

From GitHub

Chromium browsers, no setup

  1. Turn off Apple's iCloud Passwords extension. This build uses its connection.
  2. Download …-github-chrome.zip from the latest release and unzip it.
  3. On the extensions page, turn on Developer mode, click Load unpacked, and pick the folder.

Touch ID companion

Optional, Mac app

  1. Download Apple Passwords Plus.app from the releases and move it to Applications.
  2. Open it and follow the three steps: connect browsers, run in the background, allow reading the code.
  3. The extension now unlocks with Touch ID. It also does the one-time setup for you.

Questions

Is this made by Apple?

No. It's an independent open-source project that talks to software Apple ships with macOS. "Apple" and "iCloud" are trademarks of Apple Inc.

Can it see my passwords?

Only the one you choose to fill, for the site you're on, at the moment you click. It never stores them. The pairing key lives in memory and is gone when you quit the browser or press Lock.

Why does the store version need a setup step?

Browsers only let an extension start a program that a small permission file names. macOS ships that file for Apple's own extension only. The setup writes the same kind of file for this one, pointing at Apple's unmodified helper.

Why does Touch ID need Accessibility?

Touch ID can't replace the code in Apple's pairing, because the code is the pairing password. The companion reads the code off Apple's window after you confirm with Touch ID. It checks that the window really is Apple's, and it gives the extension nothing but the six digits.

Windows?

Not yet. Apple's helper on Windows works differently; it's on the list.
